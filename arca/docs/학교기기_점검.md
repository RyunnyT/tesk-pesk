# 학교 기기 점검 (프롬프트 F, 2026-11-15)

재는 법: `node arca/tools/check/perf.cjs dist [lite]` — 파일 하나 빌드(dist, 플레이 링크와 같음)를 **CPU 4배 느리게 + 태블릿 화면(1024×768)**으로 열어 잰다.
가벼운 모드 묻기는 `tools/check/lite.cjs`, 오래 켜 두기는 `tools/check/bot.cjs`(마을마다 힙·바탕 그림 크기).

## 고치기 전후 (CPU 4배 느리게)
| 항목 | 고치기 전 | 고친 뒤(보통) | 고친 뒤(가벼운 화면) |
|---|---|---|---|
| ① 그림 다 불러오기까지 | 1.9초 | 1.8초 | 1.9초 |
| ② 큰 마을(t1, 48×32칸) 들어갈 때 멈춤 | **1,972ms** | **307ms** | **206ms** |
| ② 길목(r1, 40×22칸) 들어갈 때 멈춤 | 53ms | 69ms | 33ms |
| ③ 마을에서 걷는 동안 한 장면 그리기(평균 / 느린 5%) | 11.2 / 16.6ms | 12.9 / 17.1ms | **2.0 / 3.5ms** |
| ③ 길목에서 걷는 동안 | 1.4 / 3.2ms | 1.0 / 1.4ms | 1.1 / 1.9ms |
| ④ 큰 마을 바탕 그림 메모리 | 42MB | 42MB | **19MB** |
| ④ 길목 바탕 그림 메모리 | 16MB | 16MB | 7MB |
| ④ JS 메모리 | 4MB | 4MB | 4MB |

- 장면은 1초에 20번(50ms마다) 그린다. 그리기가 50ms 안이면 끊기지 않는다.
- ② 가장 큰 원인은 지워진 곳의 연필 밑그림(`setupPatches`)이 큰 마을 전체(3배, 약 350만 점)를 훑던 것 → **지워진 칸 둘레만** 훑게 바꿈(`src/20-lite.js`). 모양은 그대로.

## 하지 않은 것과 까닭
- **그림을 맵별로 나눠 불러오기·큰 그림 한 장으로 묶기**: 플레이 링크와 파일 하나 빌드는 그림 1,994장이 파일 안에 들어 있어(6MB) 네트워크 요청이 없다. 다 불러오는 데 느린 기기로도 2초 안쪽이고, 그동안에도 옛 그림으로 바로 놀 수 있다. 효과가 작아 미룸. `index.html` 을 학교 서버에서 낱장 파일로 열 때만 의미가 있어, 그렇게 쓰게 되면 다시 본다.

## 가벼운 화면
- 메뉴 ☰ → **가벼운 화면 / 보통 화면**. 바꾸면 잠깐 다시 불러온다(진행은 저장됨).
- 화면 배율 3배 → 2배(그림 크기는 그대로, 조금 덜 선명), 흔들림 끄기, 반짝이 줄이기, 전 맵 바탕 그림 지우기.
- 느린 기기 알아채기: 맵에서 처음 30장을 재서 평균이 20ms 넘으면 한 번만 "가벼운 화면으로 바꿀까요?"를 묻는다(그동안 게임 멈춤). 빠른 기기는 세 번 재고 더 재지 않는다.

## 선생님이 실제 태블릿에서 볼 것 (5줄)
1. 플레이 링크를 열고 첫 화면이 10초 안에 나오는지, 「가벼운 화면으로 바꿀까요?」가 뜨는지 적기.
2. 마이룸 → 1부 루멘 마을로 나갈 때 멈추는 시간이 1초 안인지(가벼운 화면도 한 번씩).
3. 마을과 길목을 1분씩 걸으며 캐릭터가 뚝뚝 끊기지 않는지, 글자·버튼이 겹치지 않는지.
4. 몬스터와 싸울 때 답 구슬 버튼이 손가락으로 잘 눌리는지, 문제 띠 글자가 읽히는지.
5. 20분 켜 둔 뒤에도 느려지거나 꺼지지 않는지(태블릿 배터리·발열도 함께).
