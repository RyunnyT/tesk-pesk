# 설계안: 아르카 진행·학습 기록을 Pesk 서버에 학생별로 저장 (2026-11-18)

> 아직 만들지 않은 **설계안**입니다. 시범 운영 결과를 본 뒤 아래 「정해 주실 것」을 정하면 그대로 만들 수 있게 적었습니다.
> 관련: `docs/Pesk_베타_운영.md`(지금 체험판), `docs/학습기록_구조.md`(학습 기록 모양), `docs/설계_Pesk연결.md`(예전 제안).

## 1. 왜 필요한가 (지금의 한계)
지금 체험판은 진행(`arca-v2`)과 학습 기록(`arca-log`)을 **학생이 쓰는 기기의 브라우저에만** 저장합니다(학생마다 `@학급-번호` 로 칸을 나눔).
- 학생이 다른 태블릿을 쓰면 처음부터 다시 합니다.
- 브라우저 데이터를 지우면 진행이 사라집니다.
- 선생님이 기록을 보려면 학생마다 「학습 보고서 → 내보내기」를 해서 파일을 모아야 합니다.

서버에 저장하면 **어느 기기에서든 이어 하고**, **선생님은 대시보드에서 바로 반 전체 기록**을 봅니다.

## 2. 한 줄 요약
Pesk 가 이미 모험 기록을 저장하는 방식(`classrooms/{학급}/data/pesk-quiz-progress/students/{번호}`)과 **같은 모양**으로, 아르카 문서 두 개를 학생마다 둡니다. 서버와 주고받는 일은 **Pesk(부모 창)가 맡고**, 아르카는 Firebase 를 몰라도 되게 창끼리 메시지(postMessage)만 주고받습니다.

## 3. 저장 위치와 모양
| 문서 | 경로 | 내용 | 크기(잰 값) |
|---|---|---|---|
| 진행 | `classrooms/{학급}/data/arca-save/students/{번호}` | `{ value: save, rev, updatedAt, ver }` | 새 저장 0.6KB · 109맵을 다 걸어 본 저장 약 62KB(대부분 걸어 본 곳 표시 `save.ex`) |
| 학습 기록 | `classrooms/{학급}/data/arca-log/students/{번호}` | `{ value: log, rev, updatedAt }` | 최근 300문제 + 날짜·단원 합계, 약 45KB에서 더 커지지 않음 |

- Firestore 문서 한도는 1MiB 라서 둘 다 넉넉합니다. 진행 문서는 나중에 `save.ex` 를 압축(같은 글자 묶기)하면 10KB 아래로 줄일 수 있습니다.
- `rev` 는 저장할 때마다 1씩 늘리는 번호입니다(아래 5번 「두 기기에서 동시에」).
- 학생 이름은 넣지 않습니다. 대시보드는 Pesk 명렬표(`tesk-students`)의 번호로 이름을 붙여 보여 줍니다.
- 게임 속 별명은 지금처럼 게임 안에만 남습니다.

## 4. 흐름
1. **열 때**: Pesk 가 `arca-save`·`arca-log` 학생 문서를 읽습니다(읽기 2번).
   - 그다음 `arca.html?p=…&g=…&srv=1` 로 틀을 열고, 아르카가 준비되면 메시지 `{type:'arca-load', save, log, rev}` 를 보냅니다.
   - 아르카는 3초 동안 이 메시지를 기다리고, 오지 않으면 기기 저장으로 시작합니다(인터넷이 끊겨도 놀 수 있게).
2. **놀 때**: 아르카의 `store()`(이미 101곳에서 부름)가 기기에 저장하는 것은 그대로 둡니다. 여기에 「바뀜」 표시만 켭니다.
3. **서버로 보낼 때**: 바뀐 것이 있을 때만 다음 순간에 `{type:'arca-save', save, log, rev}` 를 부모에게 보내고, Pesk 가 서버에 씁니다.
   - **60초마다**
   - **창을 숨길 때**(`visibilitychange`)
   - **「✕ Pesk 로 돌아가기」를 누를 때**
4. **닫을 때**: Pesk 의 `closeArca()` 가 마지막 저장 메시지를 받은 뒤 틀을 지웁니다. 지금의 `arcaSaveNow` 자리에 서버 쓰기를 더합니다.

## 5. 어려운 경우
- **처음 서버를 켤 때(기기에만 저장이 있음)**: 서버 문서가 없고 기기 저장이 있으면 기기 저장을 올립니다(한 번만).
- **기기 저장과 서버 저장이 다를 때**: 「정해 주실 것 ①」. 추천은 **더 많이 진행한 쪽**(맞힌 문제 수 `save.solved`, 같으면 최근 것)을 쓰고 알림 한 줄을 보여 주는 것입니다.
- **두 기기에서 동시에**: 보안 규칙에서 `rev` 가 정확히 1 늘어날 때만 쓰기를 허락합니다. 늦게 쓴 기기는 쓰기가 거절되고 "다른 기기에서 이어 했어요. 그쪽 진행으로 다시 열까요?" 를 묻습니다. 읽기를 따로 하지 않아도 규칙이 막아 줍니다.
- **인터넷이 끊겼을 때**: 기기에는 계속 저장합니다. 다시 연결되면 다음 60초 저장 때 올립니다. 실패해도 게임은 멈추지 않습니다.
- **같은 태블릿을 여러 학생이 씀**: 지금처럼 기기 저장 칸은 `@학급-번호` 로 나뉘어 있고, 서버도 번호별 문서라 섞이지 않습니다.

## 6. 보안 규칙 (`firestore.rules` 에 더할 것)
지금 `match /data/{key}/students/{studentId}` 블록은 `pesk-quiz-progress` 만 허락합니다. 여기에 아르카 두 키를 **따로** 더합니다. 모험 기록과 달리 본인 번호 문서만 쓸 수 있게 합니다.
```
// 아르카(베타): 진행·학습 기록, 학생마다 문서 하나. 전환한 학급의 학생은 자기 번호 문서만.
function isArcaKey(key) { return key in ['arca-save', 'arca-log']; }
function arcaOwn(roomId, studentId) {
  return isStudentOfRoom(roomId) && studentId == string(member(roomId).get('studentNum', -1));
}
function arcaRevOk() {   // 두 기기 동시 저장 막기
  return resource == null ? request.resource.data.rev == 1
                          : request.resource.data.rev == resource.data.rev + 1;
}
// match /students/{studentId} 안에
allow read:  if isArcaKey(key) && (isMaster() || ownsRoom(roomId) || !isSecuredRoom(roomId) || arcaOwn(roomId, studentId));
allow write: if isArcaKey(key) && arcaRevOk() && request.resource.size() < 900000
             && (isMaster() || ownsRoom(roomId) || !isSecuredRoom(roomId) || arcaOwn(roomId, studentId));
```
- **아직 전환하지 않은 학급**(학생 Firebase 로그인 없음)은 지금 Pesk 의 다른 학생 문서처럼 학급 안에서는 누구나 쓸 수 있습니다. 이건 Pesk 전체의 지금 수준과 같고, 학급을 전환하면 본인 문서로 막힙니다.
- 저장소에 규칙 파일이 세 개(`firestore.rules`·`firestore.secure.rules`·`firestore.student-auth.rules`) 있고 모두 `pesk-quiz-progress` 블록을 가지고 있습니다. 실제로 배포하는 파일(`firebase.json` 이 가리키는 것)을 먼저 확인하고 셋 모두 같은 블록을 넣습니다. 배포는 `firebase deploy --only firestore:rules`. **배포 전 Firebase 에뮬레이터로 규칙 검사**를 합니다(아래 9번).

## 7. 사용량 (무료 한도 안인지)
- 학생 25명이 40분 놀면:
  - 쓰기: 60초마다 최대 2문서 → 약 25 × 40 × 2 = **2,000번**. 실제로는 바뀐 것만 보내니 이보다 적습니다.
  - 읽기: 여는 순간 2번 × 25명 = **50번**.
- Firebase 무료(Spark) 하루 한도는 쓰기 20,000번·읽기 50,000번입니다. 한 반 한 번 수업이면 쓰기의 약 10%입니다.
- 전환한 학급은 규칙이 학급 정보·학생 인증 문서를 확인하느라 요청마다 읽기가 1~3번 더 붙습니다(`FREE-STUDENT-AUTH.md` 의 요금·한도). 쓰기 2,000번이면 읽기 약 4,000~6,000번이 늘어 하루 읽기 한도의 약 10% 입니다.
- 여러 반이 쓰거나 Pesk 다른 기능과 합치면 Pesk 의 사용량 관리(마스터 대시보드)에서 보입니다. 필요하면 저장 간격을 90~120초로 늘립니다.

## 9. 만들 때 순서 (예상 2~3번 작업)
1. **아르카**: `src/00-pesk-beta.js` 를 넓힙니다. `srv=1` 일 때 할 일:
   - `arca-load` 받기
   - 바뀜 표시와 60초·숨김·닫기 때 `arca-save` 보내기
   - 받은 저장과 기기 저장 비교
   - 「다른 기기」 묻기
2. **Pesk 학생 앱**(`pesk.html`): `openArca` 가 읽고 보내고, 메시지를 받아 쓰고, `rev`·실패를 다룹니다. 새 파일 `shared/pesk-arca-store.js`(`pesk-quiz-store.js` 모양)로 따로 둡니다.
3. **보안 규칙**: 6번 블록 + 에뮬레이터 검사. 검사 내용:
   - 본인 문서만 쓰기
   - 다른 번호 문서 쓰기 거절
   - `rev` 건너뛰기 거절
   - 교사 읽기 허락
   - 900KB 넘기 거절
4. **교사 대시보드**: 8번 보기·지우기.
5. **검사**:
   - `arca/tools/check/pesk.cjs` 에 가짜 서버(메시지 흉내)로 열기·이어 하기·두 기기·끊김을 더합니다.
   - 실제 Firebase 는 선생님 계정으로 학생 2명·기기 2대로 확인합니다.
6. **배포 순서**: 규칙 배포 → Pesk 배포. 거꾸로 하면 쓰기가 거절되지만, 기기 저장은 남아 잃는 것은 없습니다.

## 10. 정해 주실 것
| | 질문 | 추천 |
|---|---|---|
| ① | 기기 저장과 서버 저장이 다르면 어느 쪽을 쓸까요? | **더 많이 진행한 쪽**(맞힌 문제 수 기준) + 알림 한 줄 |
| ② | 서버 저장을 학급마다 켤까요, 아르카를 켜면 늘 할까요? | 아르카를 켠 학급은 **늘 서버 저장**(스위치 하나 줄이기) |
| ③ | 학습 기록 보관 기간 | **학년 말까지**, 선생님이 지우기 단추로 정리 |
| ④ | 대시보드 기록에 Pesk 실명을 붙일까요? | **붙임**(서버엔 번호만 저장, 화면에서만 명렬표로 이름 표시) |
| ⑤ | 개인정보 안내 | Pesk 의 기존 개인정보 안내(가정 안내문)에 "수학 게임 학습 기록(문제·정답 여부·시간)"을 한 줄 더합니다 — 선생님 확인 필요 |
| ⑥ | ⚔️ 모험과 연결(코인·레이팅)도 같이 할까요? | **따로**. 서버 저장이 안정된 뒤 정하기 |

## 11. 위험과 대비
| 위험 | 대비 |
|---|---|
| 규칙 실수로 다른 학생 기록이 보이거나 써짐 | 에뮬레이터 규칙 검사를 배포 조건으로. 전환 학급은 본인 번호만 |
| 저장이 너무 잦아 무료 한도 초과 | 바뀐 것만, 60초 간격, 사용량 보고 간격 조정 |
| 두 기기 덮어쓰기 | `rev` 규칙으로 늦은 쪽 거절 + 묻기 |
| 인터넷 끊김 | 기기 저장이 기본, 서버는 덧붙임 |
| 학생이 기기 저장을 조작해 올림 | 학습 게임이라 점수 경쟁이 없고 Pesk 코인과 연결하지 않으므로 지금은 감수. 모험과 연결할 때 서버 쪽 검사 추가 |
